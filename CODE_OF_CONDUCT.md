# Code of Conduct

Round Table Workspace is for people building and reviewing AI-assisted
engineering workflows. Good contributions can be code, docs, examples,
failure-mode reports, claim-boundary reviews, or small workflow improvements.

## Expected Behavior

- Be direct, specific, and respectful.
- Keep feedback tied to evidence, reproduction steps, or a concrete workflow.
- Separate "this failed on my machine" from broader support claims.
- Protect private data, credentials, local logs, and unpublished transcripts.
- Assume claim boundaries matter: fixture-backed evidence is not the same as
  host-live or provider-live support.

## Unacceptable Behavior

- Harassment, insults, or personal attacks.
- Posting secrets, tokens, cookies, private logs, or sensitive screenshots.
- Pressuring maintainers or contributors to overstate support status.
- Repeatedly ignoring reproduction requests, safety boundaries, or claim
  boundary corrections.
- Using issues or pull requests for spam, unrelated promotion, or deceptive
  claims.

## Scope

This code of conduct applies to GitHub issues, pull requests, discussions,
release comments, and project-linked community conversations.

## Enforcement

Maintainers may edit or close issues, hide comments, block users, or remove
contributions that violate these rules. The goal is to keep the project useful
for people who want a practical, evidence-aware review gate for AI-assisted
work.

When in doubt, keep the conversation concrete: what changed, what evidence is
available, what risk remains, and what should happen next.
