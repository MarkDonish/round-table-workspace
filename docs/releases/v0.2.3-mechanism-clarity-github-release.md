## What changed

- README now explains the core mechanism in plain English: create reviewer candidates, keep the reviewers with useful signal, bring them into a round-table debate, then return `ship`, `revise`, or `reject`.
- The public Pages homepage now has a `What Actually Happens` section for faster first-read understanding.
- A one-page review packet is available for curators, newsletter writers, and teams evaluating whether the repo is worth starring or sharing.
- GitHub discovery was improved with the `coding-agents` topic.
- Four starter issues are marked `good first issue` and `help wanted` so new contributors can find small, claim-safe entry points.
- Pages publishing was adjusted for static docs publishing with `.nojekyll`; the live homepage content is updated, although the GitHub Pages API may still show an errored build status from the deployment transition.
