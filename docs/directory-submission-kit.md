## 140-Character Description

Local-first round-table review for AI coding agents before you trust generated
work.

## 280-Character Description

Round Table Workspace gives AI coding agents a review gate before you trust
their output: `/room` explores the problem, `/debate` reviews risky choices,
and `ship-check` returns `ship`, `revise`, or `reject` with local evidence.

## Longer Description

Round Table Workspace is a local-first decision layer for Codex, Claude Code,
and other CLI agent workflows.

It is built for the moment right before a developer trusts AI-generated work.
Instead of accepting one confident agent answer, the workflow creates a small
review panel, checks product value, engineering readiness, risk, and user
clarity, then returns a practical `ship`, `revise`, or `reject` decision.

The default demo path is fixture-backed and does not require provider keys. The
project is intentionally conservative about support claims: fixture-backed
demos, wrappers, and config preflight are not described as host-live or
provider-live support without fresh validation evidence.

## Best Submission Angle

For developer audiences:

> A local pre-merge review gate for AI-generated work.

For AI-agent audiences:

> A round-table decision layer that makes agents review each other before you
> trust the output.

For open-source directories:

> A local-first CLI workflow for safer AI coding decisions, with demos,
> evidence trails, and claim-boundary checks.

## What To Avoid

Do not claim:

- universal support for every local agent host
- host-live support without current validation
- provider-live support without current validation
- production stability across all machines
- guaranteed correctness for AI-generated work

Prefer:

- fixture-backed
- local-first
- review gate
- evidence trail
- claim boundary

## Submission Checklist

- Use the GitHub repo as the primary URL when stars are the goal.
- Use the one-minute demo as the secondary URL when a directory accepts a demo.
- Use `docs/distribution-checklist.md` to choose the submission order and
  tracking fields.
- Use `docs/public-submission-targets.md` for current public entry points.
- Use `docs/newsletter-roundup-pitch-kit.md` for newsletter and roundup outreach.
- Use `docs/promotion-feedback-template.md` before choosing the next copy angle.
- Keep the description focused on one idea: review AI-generated work before
  trusting it.
- Include the MIT license when a directory asks for licensing.
- Include `good first issue` only when the platform has an open-source
  contributor audience.
- Do not describe fixture-backed demos as live host/provider validation.
